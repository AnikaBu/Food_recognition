# Food Recognition 🥗 — Пошаговый план проекта

## Цель проекта
Создать систему распознавания еды по фотографии с автоматической оценкой веса ингредиентов и расчетом КБЖУ, возможностью ручной корректировки и ведением дневника питания. Проект строится по принципу **«Один мозг — три интерфейса»**: **Telegram-бот**, **PWA (веб)** и **Android-приложение (Flutter)**.

---

## Архитектура системы

```
                       [ 1. Telegram-бот ]
                              │
[ 2. Веб / PWA ] ─────> [ Бэкенд (Python / FastAPI) ] <───── [ 3. Android-приложение (Flutter) ]
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
          [ Google Gemini Vision ]  [ База данных SQLite ]
          (Распознавание и КБЖУ)    (Дневник и история)
```

### 🟢 Этап 4: Единый бэкенд API (FastAPI) (Завершен ✅)
- [x] Установка и настройка `FastAPI`, `uvicorn`, `python-multipart`.
- [x] Создание моделей запросов `SaveMealRequest`, `UpdateWeightRequest` в `models.py`.
- [x] Разработка REST API сервера в `server.py`:
  - `GET /` — проверка статуса сервера;
  - `POST /api/analyze-photo` — загрузка фото и распознавание в оперативной памяти через Gemini;
  - `POST /api/meals` — сохранение приема пищи в дневник (SQLite);
  - `GET /api/meals/{id}` — получение подробной карточки приема пищи;
  - `PUT /api/items/{id}/weight` — пропорциональный пересчет веса и КБЖУ;
  - `DELETE /api/meals/{id}` — удаление приема пищи;
  - `GET /api/diary` — получение суточной сводки и списка блюд за день;
  - `GET /api/diary/meals` — список блюд за конкретную дату;
  - `GET /api/goals`, `PUT /api/goals` — получение и сохранение суточных целей КБЖУ в SQLite;
  - Настройка CORS для будущих клиентов (PWA и Flutter);
  - Интерактивная Swagger-документация по адресу `/docs`.
